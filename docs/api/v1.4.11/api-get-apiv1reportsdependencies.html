Dependency report

GET /api/v1/reports/dependencies

GET /api/v1/reports/dependencies?pi_id=<uuid>
GET /api/v1/reports/dependencies?as_id=<uuid>&pi_id=<uuid>

Dependency analysis overview across three dimensions: peer AS dependencies (BGP/BMP), critical link pairs (topology), and SRLG/device failure candidates.

Auth: Any authenticated user.

Query parameters:

  • as_id (optional) -- Autonomous System UUID for peer AS dependency analysis (requires BMP targets)
  • pi_id (optional) -- Protocol Instance UUID for critical pairs and SRLG/device analysis
  • window (optional) -- scorecard window in hours, 1..168, default 24. Scopes the session scorecards, churn share, path half-life and the observability ledger; the live peer-AS/prefix summary is always current state. A malformed value is a 400, never silently the default.

Response: 200 OK

Severity (D-04): red = single-homed + >50% no-alternative, yellow = multi-homed with some unprotected, green = fully protected.

Scorecard block: peer_sessions carries one window scorecard per recorded session — a session that is down right now still scores (and bgp_available is true whenever session history exists, even with an empty live summary; that is exactly the BMP-settle case). Recorded uptime is clamped to the window; flaps counts in-window state transitions with seed re-baselines excluded; churn_opens counts the candidate-path opens received from that session; last_dump_seconds/last_dump_routes measure the table dump after the last session-up (receive-time based over a 10-minute horizon — an approximation by design, not a convergence measurement). Sentinel discipline: -1 means "not measurable" — no enabled history_mode: full target on the session's device (churn/dump), no sessions recorded (the aggregated summary columns), or no full-RIB history at all (median_path_life_s) — and is never conflated with a genuine quiet 0. The aggregated summary columns weight uptime by session-time, and churn_share is the AS's share of ALL measurable sessions' churn (shares sum to ≤100%). observability embeds the blind-spot ledger for the same window; read it before reading stability off quiet numbers, and treat full_rib_available: false as "churn/half-life emptiness is a coverage refusal, not stability".

ipv4_space semantics: the peer AS's unique IPv4 address space — the interval union of its distinct prefixes, so a covering aggregate and its more-specifics count once — and the report's sort key. The same union semantics apply to ipv4_space_lost, the per-device ipv4_space, and total_ipv4_space in the dependency-impact response below (the drill-down's per-prefix ipv4_space reports that one prefix's own size).
