List BGP peers

These existing reads are included in the 1.4.4 OpenAPI reference. Ordinary authenticated operator, engineer and admin credentials are supported. Restricted read-only API keys receive 403; documentation inclusion does not change access.

GET /api/v1/bgp/peers

List BGP peers discovered via BMP or SNMP BGP4-MIB walks, with optional filtering and pagination. Each peer carries source ("bmp" — BMP Peer Up/Down evidence, the richer view — or "snmp" — a bgpPeerTable walk on a router without BMP export; IPv4-ADDRESSED sessions only, and a 4-byte remote ASN appears as AS_TRANS 23456 per the MIB's 2-byte fields). prefixes_received is absent when not measured — the plain BGP4-MIB has no prefix counter; on Cisco agents the walk also reads cbgpPeerAcceptedPrefixes (CISCO-BGP4-MIB, per AFI/SAFI), which fills real counts AND surfaces the further address families a session carries as their own peer rows (an IPv6-unicast AF over an IPv4 session appears as an address_family: "ipv6" row with the session's IPv4 peer_ip). Non-Cisco agents keep the documented v4-only view with no counts.

Auth: all authenticated roles

Query params:

Param Type Description
device_id UUID Filter by device
as_id UUID Filter by autonomous system
target_id UUID Filter by BMP target
state string Filter by peer state (up, down)
peer_type string Filter by peer type (ibgp, ebgp)
af string Filter by address family (ipv4, ipv6, vpnv4, vpnv6)
limit int Max results (default 50, max 1000)
offset int Pagination offset (default 0)
at RFC 3339 As-of-T: return peer sessions from bgp_peer_history at this time instead of the live state. Malformed → 400.

Response: 200 OK

created_at/updated_at are always present. peer_bgp_id (the peer's BGP Identifier), peer_hostname (joined display name for the peer), and the timer / notification fields are omitempty — present only when populated.

total counts sessions — one row per reporting device × peer × address family, so a peer reported by six BMP-exporting routers contributes six rows (device_hostname identifies the reporter). up counts sessions in state up and unique_peers counts distinct (peer IP, AF) combinations; both are computed over the whole filtered set, not the returned page.

When at is supplied, the counts and rows come from the session history as-of-T; a notice string is added (and total is 0) when the window has no recorded sessions — BGP history may not cover the selected time.
